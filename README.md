# Tech News Publisher（科技情报简讯发布器）

一个面向 AI 编程/写作代理的自定义 Skill：把一个新闻标题或话题，研究、撰写、归档成一篇可发布的 Hexo 草稿，全程保持「科技情报分析师」的语气，反 AI 腔调，零幻觉容忍。

最终产物落在 `source/_drafts/` 下，**不会自动发布**——由作者审核后手动 `hexo publish`。

## 它解决了什么问题

很多 AI 工具能写文章，但写出来的几乎都是 AI 味浓重的「正确的废话」：堆形容词、爱总结升华、喜欢三段排比、动不动「炸裂」「重塑行业」。对于科技博客来说，这种内容毫无信噪比可言。

这个 Skill 的目标是把 AI 代理拉到一个具体的写作角色里——**科技情报分析师**——并通过明确的规则约束，让产出接近一个有判断力的人类编辑：

- 多源交叉验证（代码层 / 理论层 / 舆论层 / 报道层 / 官方层），三角验证核心数据
- 识别 PR 通稿场景，明确告诉读者「目前所有报道均转引官方口径」
- 反对偶、反三段式、反价值升华结尾
- 默认删除空洞副词与转述层，能用数字就不用「显著提升」

## 工作流程

```
研究 → 撰写 → 创建草稿 → SEO 优化 → 交付
```

| 阶段 | 做什么 |
|------|--------|
| **Stage 1 研究** | 跨 5 个层次搜集信息，三角验证核心数据，每条信息归入 A/B/C 三档 |
| **Stage 2 撰写** | 以「科技情报分析师」身份产出文章，遵循反 AI 腔调三层规范，并插入配图 |
| **Stage 3 建草稿** | `hexo new draft "<title>"`，写入正文（去掉重复标题与来源段） |
| **Stage 4 SEO** | 切换 SEO 优化师角色，grep 现有 taxonomy，配置 permalink / categories / tags / description |
| **Stage 5 交付** | 草稿路径 + 信源列表交还用户，**不执行 `hexo publish`** |

## 触发条件

当用户提供一个科技新闻话题（产品发布、融资、论文、行业事件），并表达「写一篇文章」「整理成一篇博客」「研究一下并写出来」之类的意图时，Skill 自动触发。

即便用户没有明说「Hexo」或「博客」，只要当前工作目录是 Hexo 项目（存在 `_config.yml` 和 `source/_posts/`），Skill 也会接管。

## 前置条件

- 当前目录是 Hexo 项目根目录（`_config.yml` 与 `source/_posts/` 同级）
- `hexo` CLI 已安装并可在命令行调用
- 当前 AI 代理有可用的联网检索/浏览能力（Stage 1 需要查证外部信源）

## 反 AI 腔调规则一览

Skill 内置了非常具体的禁用清单，分三层：

**第一层：禁用词与禁用句式**

过渡套话：综上所述、总而言之、不难看出、显而易见
宏大叙事：在这个 X 的时代、X 已成为不可逆的趋势、未来可期、引发广泛关注
情绪形容词：震惊、炸裂、史诗级、王炸、封神、碾压、吊打、断崖式领先、颠覆性
AI 特征句尾：…这一突破、…这一里程碑、…为 XXX 打开了新的可能性

**第二层：句式反模式**

- **反对偶**：AI 喜欢工整对称的两段式。直接陈述，长短句混用。
- **反三段式排比**：有两点写两点，有四点写四点，绝不为对称凑数。
- **反铺垫**：核心结论先扔出来，背景跟在后面。
- **反"价值升华"结尾**：不以"这意味着…"收尾。让事实自己说话。
- **反"看似 X 实则 Y"**：AI 凑深度的标志。

**第三层：信息密度自检**

写完每段问：**这段话删掉哪些字含义完全不变？** 凡是可删的删掉。

**对照示例**

❌ AI 味：
> 随着大模型技术的不断发展，某公司近日推出了 Alpha 模型，这一突破性的发布在业内引发了广泛关注。

✅ 干练：
> 某公司发布 Alpha 模型。官方称推理延迟下降 18%，API 输入价格不变。第三方 benchmark 还没有稳定复现，现阶段只能把性能提升视为官方口径。

完整规则见 [SKILL.md](./SKILL.md) 和 `examples/tone-samples.md`。

## 三档信息区分

写作时每条信息必须归入下列三档之一，绝不混淆：

| 档位 | 含义 | 处理方式 |
|------|------|----------|
| **A 档：客观事实** | 多源独立验证 / 一手官方文档 / 可复现数据 | 直接陈述 |
| **B 档：官方口径** | 有出处但无第三方验证 | **必须显式归因**：「官方称…」「据 OpenAI 博客…」 |
| **C 档：传言** | 无明确出处的小道消息 | 标「待核实」或直接剔除 |

PR 通稿特征明显时（中文媒体措辞高度相似），明确告诉读者：「目前所有报道均转引官方口径，暂无第三方独立评测/复现。」——这本身就是有价值的可信度信号。

## 配图

每篇文章在摘要 blockquote 之后必须插入一张配图。**详细流程在 `examples/image-workflow.md`**，包括选图原则、下载、用户确认话术、上传方式、失败兜底。

硬性规则：
- **跑任何图片上传命令前必须先和用户确认**，等明确肯定回复才上传
- **`image` 命令失败不要默默跳过**，明确告知用户
- **绝对不要伪造 R2 URL**

## ⚠️ 缓存与成本

本 skill 已针对 Anthropic API 的 prompt caching 优化。**对 SKILL.md 主体的任何修改都会让缓存失效**（贵 25%）。

**安全修改区**（不影响主缓存）：`examples/` 目录下的所有文件

**谨慎修改区**（会击穿缓存）：SKILL.md 本文件的任何字面修改

### 批量产文模式

连续产文时，**全部在同一个会话里连续触发本 skill**：
- 同一会话内，SKILL.md 的内容被缓存，从第 2 篇起这部分 token 价格降到 ~10%
- 跨会话（或间隔 > 5 分钟）缓存过期，按首次写入计价

实操建议：今天计划产文 ≥3 篇时，**不要关掉对话**，把多个选题在同一会话里逐个交给当前 AI 写作代理。

## 设计决策

**为什么停在草稿阶段？**

技术上让 AI 代理直接 `hexo publish` 完全可行。但发布是一个不可逆动作，且科技新闻的事实核查必须留一个人类闭环。Skill 在 Stage 5 明确写了：即使用户原始指令包含「发布到博客」，也理解为「产出一篇可直接发布的草稿」，而不是发布授权。

**为什么强制扫描已有 tag？**

新建 tag 会稀释聚合页权重。Stage 4 强制先 `grep` 已有 categories/tags，优先复用。这不是风格偏好，是 SEO 决策。

**为什么把规则写得这么死？**

「写得有人味」是个非常容易被 LLM 用礼貌话术绕过去的目标。把要求拆到禁用词清单、句式反模式、信息密度自检三层，每一层都有可对照的具体规则，反而比抽象目标更可执行。
